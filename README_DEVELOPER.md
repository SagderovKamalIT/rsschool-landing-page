# 🛠 Инструкция разработчика: сборка и деплой на GitHub Pages

Этот проект построен на базе современного сборщика **Vite** и препроцессора **Sass (SCSS)**. Ниже описаны все команды для локальной разработки, тестирования финальной сборки и автоматического деплоя на хостинг.

---

## 📌 1. Быстрый старт (Локальная разработка)

Для развертывания проекта на локальной машине выполните следующие команды:

1. **Установка зависимостей:**
   Скачивает Vite, Sass и необходимые плагины, указанные в `package.json`.
   ```bash
   npm install
   ```

2. **Запуск локального сервера (Dev-режим):**
   Запускает сервер с поддержкой Hot Module Replacement (мгновенное обновление страницы в браузере при сохранении кода).
   ```bash
   npm run dev
   ```
   *После запуска откройте в браузере адрес: `http://localhost:5173/`*

---

## 📦 2. Финальная сборка (Перед деплоем)

Перед отправкой проекта на проверку или публикацией на GitHub Pages необходимо скомпилировать файлы в чистый, оптимизированный код.

* **Команда сборки:**
  ```bash
  npm run build
  ```

### Что происходит при сборке?
Vite автоматически создаёт в корне проекта папку **`dist/`**, в которую генерируются:
* Скомпилированный и сжатый (минифицированный) CSS-файл из всех ваших SCSS-модулей.
* Оптимизированный JS-код, готовый к работе во всех современных браузерах.
* Сжатые изображения и скопированные статические ассеты.

> ⚠️ **Важно:** Файлы из папки `dist/` нельзя открывать в браузере обычным двойным кликом мыши (через протокол `file://`), так как пути к JS-модулям сломаются. Их нужно запускать только через локальный сервер.

* **Локальная проверка собранного проекта:**
  Чтобы убедиться, что в собранном проекте нет багов и все пути прописаны корректно, запустите команду:
  ```bash
  npm run preview
  ```
  *Vite поднимет сервер для папки `dist/`, имитируя поведение реального хостинга.*

---

## 🚀 3. Настройка и автоматический деплой на GitHub Pages

Чтобы ваш проект автоматически собирался и публиковался на GitHub Pages при каждом обновлении кода, рекомендуется использовать плагин `gh-pages` или встроенную команду деплоя.

### Шаг A: Проверка конфигурации Vite
Убедитесь, что в вашем файле `vite.config.js` указано правильное базовое поле `base`, соответствующее имени вашего репозитория на GitHub:

```javascript
import { defineConfig } from 'vite';

export default defineConfig({
  base: '/rsschool-landing-page/', // Имя вашего репозитория строго с косыми чертами
});
```

### Шаг B: Автоматизация деплоя через скрипты
Чтобы деплоить одной командой, добавьте пакет `gh-pages` в зависимости:
```bash
npm install gh-pages --save-dev
```

И добавьте следующие команды в блок `"scripts"` вашего файла `package.json`:
```json
"scripts": {
  "dev": "vite",
  "build": "vite build",
  "preview": "vite preview",
  "predeploy": "npm run build",
  "deploy": "gh-pages -d dist"
}
```

### Шаг C: Запуск деплоя
Теперь, чтобы опубликовать обновленный сайт в сети, достаточно прописать в терминале всего одну команду:
```bash
npm run deploy
```
*Скрипт автоматически запустит сборку проекта (`npm run build`), создаст в вашем GitHub-репозитории скрытую ветку `gh-pages` и загрузит туда всё содержимое папки `dist/`.*

В настройках репозитория **GitHub -> Settings -> Pages** убедитесь, что источником (Source) выбрана ветка `gh-pages`. Сайт станет доступен в течение 1–2 минут!
